# 早期运行规则（经验学习版本）

这份文档逐条说明系统在每种情况下会怎么做、留下什么记录，以及哪个测试覆盖它。所有规则均由程序确定性执行，规则版本写入每次运行的配置指纹（`router-v1`、`reuse-v1`、`retrieval-v2`、`upgrade-rule-v2`、`eval-3`、`agent-prompt-v3`）。

## 1. 适用范围

| | 说明 |
| --- | --- |
| **能做** | 有自动验证器的程序优化任务：输入输出契约固定，正确性可以用参考输出判定，指标可以测量（这里是运行时间）。当前有 3 个任务族：分组聚合（`groupagg`）、访问日志统计（`logstats`）、区间合并（`intervals`）。 |
| **怎么扩展** | 新任务族只需实现一个模块：契约、初始程序、数据生成器、参考实现、输入概况与 5 个条件分桶、公开规则用例、输出检查器（`backend/src/quotacrux/families/`）。评测器、分流器、经验库和界面都不用改。 |
| **不在范围** | 无法用程序自动验证的任务（如开放式问答、写作等）；该版本经验库仅收录经评测器验证的记录。 |
| **边界限制** | 跨任务族复用经验（检索和复用均限定在同族记录内）；多 Agent 协作；联网或文献检索；非标准库依赖。 |

## 2. 分流：每次运行只走一条路线

首次模型请求之前，程序先复验经验中的已验证程序，再根据经验快照对本任务的覆盖情况决定从哪个模型开始。判断只用记录中的事实：任务族、5 个条件分桶的匹配数，以及记录的结果是成功、无收益还是失败。

| 顺序 | 条件 | 做法 | 留下什么 | 测试 |
| --- | --- | --- | --- | --- |
| 1 复用 | 快照里有同族成功记录，且带完整程序（最多取 3 个，条件最接近者优先） | 程序在本任务的开发数据上逐个复验，不调用模型；有一个达标，评测和在线模式就直接交付 | 在线模式下，复验结果写成新经验（`reuse_candidate`），说明这个程序在新条件下是否仍然成立 | `test_new_family_goes_to_the_large_model_and_online_memory_serves_the_next_task` |
| 2 相近 → 小模型 | 复验没有达标，但有同族成功记录与本任务至少 3/5 项条件相同 | 先用本地 Qwen；连续 2 次候选未达标，或 3 次请求仍无达标候选，就按升级规则切换到 GPT | 验证过的候选写入经验 | 同上（学习运行一段）；`test_small_model_stalling_triggers_upgrade` |
| 3 全新任务族 → 大模型 | 快照里没有这个任务族的任何记录 | 直接交给 GPT，全部请求预算都给它 | 首次验证结果写入经验，下一个同类任务先复用 | `test_new_family_goes_to_the_large_model_…` |
| 4 新条件 → 大模型 | 有同族记录，但没有一条成功记录与本任务至少 3/5 项条件相同 | 直接交给 GPT | 同上 | `test_family_records_without_a_similar_success_route_as_new_conditions` |

其他规则：

- 经验检索与复用均限定于同任务族：例如分组聚合的经验不用于访问日志任务。
- 一个程序如果有失败或无收益记录，且该记录与当前负载匹配的特征数，多于它任何一条成功记录的匹配数，这个程序就不复用。
- 分流器可以关闭（`--no-router`，用于对照实验）。关闭后一律先用小模型，配置指纹随之改变，所以不会与开启时的运行混在同一组对照里（`test_router_off_always_starts_small`）。

## 3. 三种模式与写入权限

| 模式 | 读经验 | 复用达标后 | 写入经验 | 允许的任务批次 |
| --- | --- | --- | --- | --- |
| 评测 `eval` | 读取指定快照 | 直接交付 | 不写 | 任意批次 |
| 在线 `online` | 读取指定快照 | 直接交付 | 交付后发布新快照，并设为生效版本 | 只限可写批次 A、S、T、smoke |
| 学习 `learn` | 读取指定快照 | 把本次目标提高到超过已知最佳 5%，交给模型去超越 | 发布新快照 | 只限可写批次 |

- 留出批次（B、C、D）只能用评测模式，在线和学习模式都会被拒绝（`test_held_out_tasks_cannot_write_and_streams_need_learnable_tasks`、`test_learning_publishes_snapshot_and_rollback`）。
- 对照开始前，会检查每个对照任务是否曾为两侧快照贡献过经验；贡献过的任务不能当留出任务（`test_comparison_is_fair_alternating_and_rejects_leaks`）。
- 快照不可变。学习或在线运行进行中，不能切换生效版本；切换（回退）只影响之后的运行，历史全部保留。

## 4. 什么算成功

| 层级 | 判定 |
| --- | --- |
| 正确 | 开发数据上的输出与参考输出一致（只容忍行尾差异），而且全部公开规则用例都通过（分组聚合 7 个、访问日志 7 个、区间合并 7 个）。只对当前数据分布正确的程序会在规则检查用例上失败（`test_unchecked_groupby_passes_dev_but_violates_contract`）。 |
| 改善 | 基线与候选交替计时 5 轮，候选的全部样本都比基线的全部样本快，才算改善。加速比是两者中位数之比。 |
| 达标 | 改善，且加速比 ≥ 1.10。学习模式下以本次提高后的目标为准。 |
| 交付 | 循环结束后冻结最佳候选，在隐藏的最终数据上测一次；结果正确、有改善且达到目标时计为达标，否则记为未达标。 |

## 5. 预算、错误与异常

| 情况 | 系统行为 | 记录 |
| --- | --- | --- |
| 模型请求用完（6 次） | 停止，交付当前最佳 | 终止原因 `budget_exhausted` |
| 候选用完（4 个） | 停止，交付当前最佳 | 同上 |
| 循环时长到 300 s，或剩余不足 15 s | 不再发新请求；复验也会提前结束 | 同上 |
| 单次请求超时（120 s）、网络错误、限流、5xx | 记为接口错误；连续 2 次，或遇到配置错误、4xx，停止运行 | `model_api_error`（`test_consecutive_api_errors_stop_run`） |
| 回复不是合法 JSON 或动作无效 | 记为无效动作，带着反馈继续；这次请求照样消耗预算 | 步骤状态 `invalid_action` |
| 候选有语法错误或引用非标准库 | 消耗一个候选，计一次未达标，不进入沙箱 | `static_check_failed` |
| 输出错误、违反契约、运行错误、超时、内存超限 | 不替换最佳，候选与反例保留，计一次未达标 | 评测记录带失败类别和具体反例（`test_failures_keep_best_and_trigger_upgrade`） |
| 计时过程中输出发生变化 | 判为不稳定，不计改善 | `unstable` |
| 沙箱或基线自身失败 | 停止，不发布经验（可能是环境问题） | `environment_error` |
| 用户点击停止 | 当前步骤结束后停止，不做最终测试 | `user_stopped` |
| 进程被杀 | 下一次运行开始时，把残留的 `running` 记为中断 | `process_interrupted` |
| 同时发起两个运行 | 全局运行锁拒绝第二个，避免计时互相干扰 | `test_runs_are_serial` |
| 未注册的任务族或任务 | 直接拒绝 | `ValueError` / `KeyError` |

候选程序在 Docker 沙箱中运行：断网、根文件系统只读、1 CPU、1 GB 内存、最多 64 个进程、非 root 用户。参考输出和最终测试数据不进入容器。

## 6. 复用与记忆的边界

- 复用快照中的已验证程序，每次都在新任务数据上重测，达标后交付。
- 复用达标即交付，不追求本任务的最优解。想在已知最佳之上继续提高，用学习模式。
- 复验过的程序，结果无论成败都写成新经验，下次据此决定是否跳过。
- 经验只来自程序从运行记录中提取的事实。模型的解释另外保存，并标为"未验证"；系统不额外调用模型做总结。

## 7. 已知局限

- 条件分桶是人工定义的 5 个特征，阈值固定。落在分桶边界附近的任务，可能被判为相近或不相近，与直觉不符。
- 复验通过的程序在新条件下也许不是最优：带记忆时交付更快、更便宜，但单个任务的加速比可能低于为它专门研究出的方案（数字见 [实验结果](memory-learning-results.md)）。
- 只验证了 3 个任务族，都是单文件、只用 Python 标准库、输入走 stdin 的程序。
- 费用是按带版本的官方价表估算的；本地 Qwen 没有 API 费用，机器成本没有核算。
- 分流阈值（至少 3/5 项条件相同）沿用了检索阈值，没有单独调优。
