# RouteEvo 日新方向增量 PRD

版本：v0.3；更新日期：2026-11-14；状态：未采用方案，保留为历史参考。

团队已确认选择 [Research Agent](../requirements/research-agent-track-prd.md)。下文保留此前日新方案，涉及的两轮任务编排、三行进化说明等日新专属要求不属于当前开发范围。

## 1. 产品目标与赛事边界

产品目标：系统从第一轮的实际执行结果中自动积累经验，在第二轮的新任务上改变行动选择，并用独立验证证明效果。

按[日新赛题说明](https://tcnf5s7xd39g.feishu.cn/wiki/EpxXwbYkkieZrfk0QbRc7wWQnRc#doxcnJ6ECkTC7W3BeJJXUZM5Uid)，需要展示前后运行、反馈带来的改进、学到了什么以及如何回退。两轮之间不能人工修改代码、参数或提示词。单次运行最好不超过一分钟，属于演示时长建议。

本项目采用程序反馈和自动经验更新。固定模型与系统指令，让经验成为前后对照的主要变量；不需要训练模型权重。

### 成功标准

- 第一轮结果实际进入新经验快照，第二轮实际读取相关经验。
- 在同一批留出任务上，质量满足预先确定的约束，成本或耗时改善；或在相同预算下任务结果更好。
- 展示具体经验、来源验证、行为变化及完整成本，而非仅展示“记忆条数增加”。
- 一键切换回旧快照，后续任务确实读取旧版，历史记录仍可追溯。

## 2. 最小场景与用户流程

默认使用共用核心的小型数据处理程序任务。先选择一个任务族，提供不同实例、可信验证及经验不适用的情况，不同时扩展多个业务场景。

首版采用已正确的分组聚合程序优化，模型与运行环境按[开工决策](implementation-decisions.md)执行。固定 Qwen、GPT-6.1 Sol（xhigh）及升级规则；改进来自自动经验更新。完整评测使用 A/B/C，下面的 B 表示两轮演示中的冻结对照批次；团队利用 B 调参后，最终独立收益由封存的 C 验收。

操作流程：

1. 打开演示会话，查看任务清单、预算和初始快照 v0。
2. 开始第一轮，系统执行 A 批任务并保存验证结果。
3. 系统自动整理合格经验、创建 v1，并显示与 v0 的差异。
4. 点击开始第二轮或由会话继续执行，系统用 v1 处理未参与学习的 B 批任务；该操作不改变策略配置。
5. 查看 v0 与 v1 对同一 B 的对照，以及提供给决策器的经验来源。
6. 在两轮展示后或评委要求时执行回退，再运行一个验证任务，确认生效快照已经恢复。

## 3. 新增功能需求

| 编号 | 功能 | 具体要求 |
| --- | --- | --- |
| RX-01 | 演示会话 | 将 A、B、v0、预算、模型、提示词和评测器版本绑定成一次会话；开始前确认清单 |
| RX-02 | 两轮编排 | 支持第一轮、自动学习、第二轮、完成或中止；每个阶段保留开始和结束状态 |
| RX-03 | 自动经验发布 | 第一轮结束后由程序核对记录来源与完整性，自动生成 v1；不依赖人工选经验或编辑结论 |
| RX-04 | 学习证据 | 展示新增或修订的经验、适用条件、来源步骤和验证结果，能够跳转到原始执行记录 |
| RX-05 | 行为对照 | 展示同一任务在旧新快照下的实际行动、尝试次数和结果；记录实际提供给决策器的经验 |
| RX-06 | 同任务评测 | 用相同初始产物和配置，在 B 上分别运行 v0、v1，得到逐任务与汇总结果 |
| RX-07 | 回退联动 | 切回 v0 后明确显示生效版本，并确保新运行没有读取 v1 或继承上一轮候选代码 |
| RX-08 | 进化说明导出 | 从实际对照、经验差异和回退记录生成三行说明及证据链接 |

两轮之间的模型、提示词、工具、评测器与预算配置保持一致；配置指纹不一致时，将该次结果标记为不可用于经验增益对照。

## 4. 两轮演示与科学对照的关系

A 用于学习，B 用于观察新任务上的效果。A 比 B 慢，不能单独证明系统进化，因此增加下面的对照：

| 执行 | 用途 | 经验写入 |
| --- | --- | --- |
| v0 执行 A | 获取第一轮执行反馈 | 结束后自动产生 v1 |
| v0 执行 B | 旧经验下的对照结果 | 禁止写入持久经验 |
| v1 执行 B | 新经验下的留出结果 | 禁止写入持久经验 |

v0 对 B 的评测可作为第二轮的独立对照运行，或使用同配置、可追溯的预先评测记录。预先记录必须标明时间、配置与来源；其输入、答案和反馈不得进入生成 v1 的学习过程。

若现场执行双路径，两个 Run 使用同样的预算与一致的并发设置。分别报告两条路径的费用，并另列整个演示的额外对照开销，不将额外费用只算入某一版本。

前后性能结论采用预先约定的统计方法；现场单次结果作为一次观测，不隐藏失败或只选择最好的一次。

## 5. 经验内容与使用边界

经验首先记录“在这些条件下，采取这个动作，出现了这些验证结果”。首版不自动改写系统提示词，不发布未经验证的通用规则。

必须覆盖三种情况：

- 成功经验能被相关的新任务检索，并可能改变执行顺序。
- 失败经验能帮助避免重复尝试，且保留失败的具体条件。
- 不满足适用条件时，旧经验不会被当成必然结论；系统可以补充证据或采用原处理流程。

界面展示实际注入的经验及行为对照。模型生成的解释单独标识，不能把一段事后解释当作经验有效的唯一证据。

## 6. 数据与界面增量

演示会话关联现有 Task、Run、MemorySnapshot 和 Comparison，不新增独立执行服务。

| 增量信息 | 用途 |
| --- | --- |
| A、B 任务清单及版本 | 说明哪些任务用于学习、哪些用于留出评测 |
| 会话配置指纹 | 核对模型、指令、工具、预算与评测条件 |
| 第一轮与第二轮 Run 标识 | 还原阶段顺序和成本 |
| v0、v1 与经验差异 | 说明新增经验及其来源 |
| 对照 Run 与回退记录 | 验证前后效果及回退是否生效 |

界面在共用页面上增加轮次状态、v0/v1 差异和三行说明区域。保留质量指标与失败案例入口，不以费用下降覆盖质量下降。

## 7. 演示与交付

建议演示顺序为：说明任务和指标、执行第一轮、展示自动学习、执行第二轮、展示同任务对照，最后按需回退。任务规模按真实测得的耗时选择，不承诺未经测量的秒数或节省比例。

三行说明模板由实际记录填充：

1. **比什么：**在固定质量约束下，对比同一 B 批任务的完成结果、Token、费用和总耗时，并单列学习成本。
2. **学到什么：**列出 v0 到 v1 的具体经验、来源验证以及后续行动变化。
3. **如何回退：**切换生效快照到 v0，以新运行的版本标识和经验输入确认回退，保留两版日志。

除赛事要求的代码、PPT 和项目说明外，项目交付包括任务与配置清单、两轮记录、旧新版本对照、经验快照与差异、三行说明和复现入口。

## 8. 方向验收

| 编号 | 验收条件 |
| --- | --- |
| RX-AC-01 | 两轮之间无需人工修改代码、参数、提示词或经验内容，v1 自动生成并被第二轮使用 |
| RX-AC-02 | 能追踪每条展示经验到第一轮的真实执行和验证记录 |
| RX-AC-03 | 同一 B 的旧新版本对照条件一致，B 未进入 v1 的学习来源 |
| RX-AC-04 | 至少覆盖同类新实例与经验不适用情况，保留全部结果 |
| RX-AC-05 | 质量、全流程成本和耗时符合共用 PRD 的统计方法；不预置“接近 100%”或固定降本比例 |
| RX-AC-06 | 回退后的新运行读取 v0，且从相同初始产物开始，v1 记录仍可查看 |
| RX-AC-07 | 三行说明中的指标、经验和回退方式能分别定位到实际证据 |

功能验收通过后，是否具备参赛中的“变好”证据，由留出对照结果决定。没有收益时明确展示结果并修正方案，不能仅用功能完整替代效果证明。

## 9. 实现顺序与可后置内容

1. 在共用 M2 上完成 RX-01—RX-03，使两轮与自动经验更新连通。
2. 完成 RX-04—RX-07，接入 M3 的冻结对照与回退。
3. 完成 RX-08、复现材料与现场展示节奏。

专用决策模型、更复杂的模型路由与经验检索、更多任务族均可后置。若调整已确定的 Qwen/GPT 配置，须重新记录配置并独立比较，不将模型更换产生的收益归入经验学习。
