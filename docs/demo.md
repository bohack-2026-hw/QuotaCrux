# RouteEvo 现场演示脚本（Research Agent）

目标时长 6—8 分钟。顺序按 PRD 第 11 节：研究问题、预算和基线 → 一条真实的证据—假设—实验—修正链 → 最佳方案、独立结果和资源账本 → 系统本身的评估。所有内容都来自真实运行记录；现场新跑的运行和事先完成的评测分开说明，不把历史实验说成现场执行。

## 0. 开场前（提前 15 分钟）

```sh
open -a OrbStack                                 # Docker
ollama ps                                        # 确认 qwen3.8:27b-mlx 已加载；没有就先跑一次 probe 预热
cd backend
uv run routeevo probe small                      # Qwen 预热，期望 10—20 s 内返回 propose_candidate
uv run routeevo probe large                      # GPT 连通性，约 20 s、约 $0.01
uv run routeevo snapshots list                   # 确认生效版本是 v6（* 标记）
uv run routeevo serve                            # 浏览器打开 http://127.0.0.1:8000
```

- 浏览器全屏，缩放 110%—125%，投影上数字要清楚。
- 确认没有运行在执行（左下角显示“空闲”）。

## 1. 研究问题、预算和基线（1 分钟）

打开「01 研究运行」，选 A-01 的学习运行（`#run/run-20261113T161733-7c5a`），展开“研究任务 · 运行开始前固定”：

- 研究问题：在输出完全正确的前提下，能否让这段分组聚合程序在该工作负载上至少快 1.10×？
- 基线：初始程序（csv + 两个 dict + sorted），开发数据中位耗时 0.679 s。
- 允许修改、工具、验证方法、预算（6 次请求、4 个候选、300 秒）都在开始前固定，模型改不了；最终测试数据不可见。

## 2. 一条真实的研究链（2 分钟）——“反馈改变了下一步”

同一页往下看“假设与实验”和“决策账本”：

1. Qwen 的假设：按字节解析、bytes 作 key 能省掉 str 转换，预期 ≥ 1.10×。实测 **0.90×，判定被反驳**。
2. Qwen 据此修正：“c1 慢是因为 bytes key”，改用 str key——但输出格式错误，**未能检验**。
3. 连续两次未达标，程序按固定规则**升级到 GPT**（账本写明触发条件）。
4. GPT 读到具体反馈（表头格式错误、c1 的慢因），提出批量分行 + 单字典原地更新：**1.45×，得到支持**，达到目标后停止。
5. 强调：判定由程序根据评测给出，不是模型自评；失败和被反驳的实验都留在记录里。

## 3. 交付：最佳方案、独立结果、资源账本（1 分钟）

- 顶部四个状态分开：候选运行完成、开发验证通过、指标改善、最终测试达标——“跑完”不等于“成功”。终止原因“开发数据达标”只说明循环为何停止；冻结的 c3 在隐藏最终数据上单独测一次：正确，1.44×。
- 资源：3 次请求、7,743 / 3,045 Token、$0.029、113 秒。
- 点“导出研究记录（Markdown）”；完整交付包见仓库 `docs/research/`：研究记录、`best.py`、全部候选、原始模型调用、`reproduce.sh`。
- 对照一个“没有验证出改进”的案例：`docs/research/` 中 A-05，三个假设全部被反驳，预算耗尽后交付初始程序，如实写“无改进”。

## 4. 系统本身的评估（2 分钟）——“经验让下一次研究更省”

打开「00 总览」：

1. A 批 6 个任务串行学习，v0 → v6，13 条经验（成功 4、无收益 8、失败 1）。经验由程序从评测事实中提取，不额外调用模型。
2. B（开发对照）与 C（最终留出）：同一配置，只换经验快照，各 6 任务 × 3 次，全部运行计入。C：达标 16/18 → 16/18，请求中位数 3 → 1，升级到 GPT 11 → 5 次，失败候选 6 → 1，费用 $0.372 → $0.292，循环时长中位数 84 → 50 s；学习成本另计 $0.149。
3. 如实讲代价：v6 一次达标就停，较少升级到 GPT，C 的最终加速比中位数 1.41× → 1.29×。学到的是更省的达标路径，不是更高的上限。
4. 进入「03 对照结果」看逐任务的点图；B-05 是经验不适用的反例，据此修改了升级规则，C 在新规则下验收。

## 5. 可选：现场自我迭代（3—5 分钟）

总览页底部“自我迭代演示”卡片：第一轮选 A-02（或 A-04、A-06），第二轮选一个 B/C 任务，基础快照选 v0，点击开始。程序依次：学习运行（读 v0）→ 自动发布新版本 → 第二轮在 v0 与新版本下各跑一次同一任务 → 自动生成结论。彩排实测一次（A-02 → v7 → B-04）用时 4.7 分钟。

单次结果只验证流程，不作为效果证据。发布的新版本会自动成为生效版本；演示后在「04 版本管理」切回 v6（或 `uv run routeevo snapshots activate v6 --reason 演示结束恢复`）。

如果现场模型请求失败或超时：账本会如实显示“接口错误 / 超时”和终止原因，然后切回事先完成的运行继续讲。

## 6. 回退（30 秒）

「04 版本管理」：选 v0，填写原因，设为生效版本，指针历史新增一行；之后的运行读取 v0，v6 和所有记录仍在。演示后切回 v6。

## 7. 常见问题

| 问题 | 回答要点 |
| --- | --- |
| 这是研究还是在轮流试预设选项？ | 没有预设候选清单；每个假设由模型根据上一个实验的实测结果写出，账本里能看到“c1 慢是因为……”这类直接引用反馈的修正。 |
| 经验是模型自己总结的吗？ | 不是。程序从结构化执行记录中提取事实；模型的解释另存为未验证假设，不额外调用模型做总结。 |
| 怎么防止模型作弊？ | 候选在禁网、只读的容器里运行，只拿到 stdin；参考输出和最终测试数据不进容器；7 个契约用例防止只对当前数据分布正确的程序。 |
| 加速是不是噪声？ | 交替测量 5 轮，只有全部候选样本快于全部基线样本才算改善；同一个程序测出 1.05× 也不会被记成改善。 |
| B 和 C 有什么区别？ | B 用于开发期对照，可以据此调整；C 在配置冻结后只跑一轮，结果不用于调优。 |
| 费用怎么算？ | 每次调用记录服务方返回的用量，按带版本的官方价表估算；没有用量就记“未知”，不写 0；本地 Qwen 无 API 费用，机器成本单列为未核算。 |
