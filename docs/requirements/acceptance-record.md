# Research Agent 验收记录

第 1—4 节记录 PRD v0.3 的实现和历史结果，第 5 节记录 v0.4 新增要求的进度。各项按[产品需求](product-requirements.md)编号，实际实验记录从[批次索引](../research/README.md)进入。

依据：[Research Agent 主线 PRD](product-requirements.md) 第 5 节（RA-01—RA-08）与第 10 节（RA-AC-01—RA-AC-08）、[补充说明](competition-brief.md) comment4。数字均来自[实验结果](../archive/memory-learning-results.md)，样例来自[研究成果样例](../research/)，都由运行记录生成。

系统有三版配置，每版都完整运行和报告。第一版的经验只有文字记录；第二版的经验另外保存完整的已验证程序，新任务先由程序复验，学习运行在已知最佳上继续超越；第三版加入分流器（相近的任务交给本地小模型，全新的任务族或新条件直接交给大模型）、在线模式（交付后写入经验）和两个新任务族。第一版的 C 对照是第二版修改的依据，第二版的最终验收用实现前封存的 D 批；第三版用运行前封存的 S 任务流验收。各种情况的处理见[边界条件](../archive/legacy-runtime-rules.md)。

## 1. 功能需求

| 编号 | 实现 | 在哪里看 |
| --- | --- | --- |
| RA-01 研究任务定义 | 任务包冻结研究问题（契约）、初始程序、开发/最终数据、目标，覆盖 3 个任务族；运行创建时冻结预算、工具、模型、评测器、复用与分流规则，写入配置指纹 | 运行页“研究任务 · 运行开始前固定”；研究记录“研究任务”节；`backend/tasks/lock.json` |
| RA-02 证据管理 | 取证工具（cProfile）与每次评测都有记录 ID；评测反馈只给测得事实（状态、加速比、失败类别、公开反例）；模型解释单独标为“未验证” | 运行页决策账本；经验卡片“测得事实 / 模型解释”分栏 |
| RA-03 假设与实验 | 每个实验执行前写下目的、预期结果和验证方法：模型候选由模型写，复用的程序由程序依据经验记录写明来源、原实测结果与条件差异；评测后由程序按当时目标判定：支持、部分支持、反驳、未能检验 | 运行页“假设与实验”（复用实验带“复用”标记）；研究记录同名表；结果第 4 节统计 |
| RA-04 反馈驱动调度 | 每步状态包含上一结果、已试方向、剩余预算；复验结果决定是否调用模型，学习运行据此提高目标；复验未达标时分流器按经验覆盖情况选择起始模型；连续未达标按固定规则升级到 GPT；每个决定都记录依据 | 决策账本“→ 下一步”；“分流”“提高本次目标”“升级模型”步骤分别写明依据 |
| RA-05 候选比较 | 只有通过且全部样本快于基线的候选才能替换最佳；复用的程序与模型候选同一规则；失败与退化候选保留代码和评测 | 运行页候选加速比条（↺ = 复用）；`report.json` 的 `best_rule` |
| RA-06 最终独立评价 | 循环结束后冻结最佳候选，在隐藏最终数据上测一次；最终数据不进容器、不进检索、不回流 | 运行页第四个状态“最终测试达到目标”；研究记录“独立最终测试” |
| RA-07 成果复现 | `export-run --bundle` 导出研究记录、最佳程序、全部候选、原始模型调用、报告与复核脚本；`experiment.sh` 重跑整条流水线 | [研究成果样例](../research/)；`reproduce.sh` |
| 原 RA-08 系统对照 | 同一 Agent、同一配置，只换经验：第三版 S 任务流带记忆 vs 不带记忆（12 任务 × 3 次重放，每次重放从起点重新学起）；第二版 B 开发对照 + D 封存留出，第一版 B + C（各 6 任务 × 3 次，交替串行） | 对照页；[实验结果](../archive/memory-learning-results.md) 第 1—4 节 |

| RA-AC-06 总成本覆盖完整过程，预算不足时正确结束 | 每次模型调用记录用量与估算费用，未知记“未知”不记 0；复验的评测时间计入循环时长；学习阶段成本沿快照链单列（第二版两轮 $0.455）；预算耗尽后交付当前最佳、不再为总结调用模型 | 满足 |
| RA-AC-07 从固定输入重跑最佳方案与评价 | A-01 样例的 `reproduce.sh` 复核：最终数据正确、1.44×（记录值 1.4367×）；第二版 D-01 样例复核：正确、1.4473×（记录值 1.4481×）；环境（沙箱镜像 ID、容器 Python 版本、Docker 服务信息、资源额度）随运行保存；`scripts/experiment.sh` 重跑两轮学习与 B、D 对照 | 满足 |

## 3. 系统本身的评估（comment4）

**第三版 · S 任务流**（从 v19 出发，12 个任务、3 个任务族，3 次重放；不带记忆 → 带记忆）：

| 问题 | 结果 |
| --- | --- |
| 研究成果：带来多少提升 | 达标 36/36 → 36/36；最终加速比中位数 1.86× → 1.86× |
| 用了多长时间 | 单次研究循环时长中位数 31s → 14s；总耗时 1486s → 1064s |
| 花了多少 Token | 模型请求 27 → 6 次；输入 69,420 → 15,312，输出 27,693 → 6,172 |
| 云端模型成本 | 大模型请求 27 → 6 次，费用 $0.402 → $0.086；学习发生在任务流内部，费用已计入带记忆一侧 |
| 能否自我迭代并改进 | 新任务族首次出现时由分流器直接交给大模型，结果写入经验；其余任务带记忆时 30/30 次没有调用模型（不带记忆 9/30）；经验条数每次重放 59 → 77 / 59 → 77 / 59 → 77 |

分流器对照（4 个新任务族的 T 任务，从 v19 出发，各 12 次）：分流关闭（先用本地 Qwen）达标 12/12、最终加速比中位数 2.11×、循环时长中位数 49s、费用 $0.047；分流开启（直接用 GPT）达标 12/12、2.18×、33s、$0.188；直接用 GPT 更快、第一个答案更好，代价是每个新任务多花约一美分。

## 4. 当时待完成的功能

- 专用决策模型对照（PRD §9 可选项）：已实现独立动作路由、模型路由与 Decisions provider 适配器；四组合实际功能检查 和历史回放结果见[路由适配器](../design/action-model-routing.md)与[决策模型实验](../archive/decisions-experiments/README.md)。当前 Decisions 路由用于非 native 的 legacy 运行；native 与 feedback/independent 研究评测保持 llm + rule 和固定生成模型。四组合入口统一关闭初始经验分流，路由请求计入总预算；现有 功能检查记录保留，完整系统收益仍待正式对照。
- 多个独立 Agent、开放式文献检索、跨领域研究：未实现；首版只做一个研究循环，覆盖 3 个软件优化任务族。无法用程序验证的任务刻意不做，因为经验只存经过评测器验证的事实。
- 复验未达标时，复验过的程序都留在提示词里，GPT 单次请求更长（第二版 B 的 B-05：平均输入 3.4k → 11.4k token）；只保留最佳一个程序是已知的下一步改进，未在本次冻结配置中修改。
- 对照页的“过程中最佳开发验证结果”在每次运行的运行页查看，对照页汇总最终验收结果。
