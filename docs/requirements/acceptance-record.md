# Research Agent 验收记录

第 1—4 节记录 PRD v0.3 的实现和历史结果，第 5 节记录 v0.4 新增要求的进度。各项按[产品需求](product-requirements.md)编号，实际实验记录从[批次索引](../research/README.md)进入。

依据：[Research Agent 主线 PRD](product-requirements.md) 第 5 节（RA-01—RA-08）与第 10 节（RA-AC-01—RA-AC-08）、[补充说明](competition-brief.md) comment4。数据源自[实验结果](../archive/memory-learning-results.md)与对应运行记录，样例归档于[研究成果样例](../research/case-studies.md)。

早期经验学习系统依次完成三版迭代并均已归档报告：第一版经验仅存文字记录；第二版另外保存完整已验证程序，新任务先由程序复验，学习运行在已知最佳上继续超越；第三版加入分流器（相近任务交由本地小模型，全新任务族或新条件直接交给大模型）、在线模式（交付后写入经验）与两个新任务族。C 对照用于第二版设计诊断，第二版以实现前封存的 D 批验收，第三版以运行前封存的 S 任务流验收；各类边界条件见[历史运行规则](../archive/legacy-runtime-rules.md)。

## 1. 功能需求

| 编号 | 实现 | 在哪里看 |
| --- | --- | --- |
| RA-01 研究任务定义 | 任务包冻结研究问题（契约）、初始程序、开发/最终数据与目标，覆盖 3 个任务族；创建运行时冻结预算、工具、模型、评测器、复用与分流规则，写入配置指纹 | 运行页“研究任务 · 运行开始前固定”；研究记录“研究任务”节；`backend/tasks/lock.json` |
| RA-02 证据管理 | 取证工具（cProfile）与每次评测都有记录 ID；评测反馈仅包含测得事实（状态、加速比、失败类别、公开反例）；模型解释单独标为“未验证” | 运行页决策账本；经验卡片“测得事实 / 模型解释”分栏 |
| RA-03 假设与实验 | 执行前写下目的、预期结果与验证方法：模型候选由模型填写，复用程序由系统依据经验记录自动生成来源、原实测结果与条件差异；评测后由程序按当时目标判定：支持、部分支持、反驳、未能检验 | 运行页“假设与实验”（复用实验带“复用”标记）；研究记录同名表；[实验结果](../archive/memory-learning-results.md)第 5 节 |
| RA-04 反馈驱动调度 | 每步状态包含上一结果、已试方向、剩余预算；复验结果决定是否调用模型，学习运行据此提高目标；复验未达标时分流器按经验覆盖选择起始模型；连续未达标按固定规则升级到 GPT；每项决策均记录依据 | 决策账本“→ 下一步”；“分流”“提高本次目标”“升级模型”步骤分别写明依据 |
| RA-05 候选比较 | 仅通过且全部样本快于基线的候选可替换最佳；复用程序与模型候选采用同一规则；失败与退化候选保留代码与评测记录 | 运行页候选加速比条（↺ = 复用）；`report.json` 的 `best_rule` |
| RA-06 最终独立评价 | 循环结束后冻结最佳候选，在隐藏最终数据上单次验收；最终数据不进容器、不进检索、不回流 | 运行页第四个状态“最终测试达到目标”；研究记录“独立最终测试” |
| RA-07 成果复现 | `export-run --bundle` 导出研究记录、最佳程序、全部候选、原始模型调用、报告与复核脚本；`experiment.sh` 重跑整条流水线 | [研究成果样例](../research/case-studies.md)；`reproduce.sh` |
| 原 RA-08 系统对照 | 同一 Agent、同配置下仅切换经验：第三版 S 任务流带记忆 vs 不带记忆（12 任务 × 3 次重放，每次从起点重新学起）；第二版 B + D、第一版 B + C（各 6 任务 × 3 次，交替串行） | 对照页；[实验结果](../archive/memory-learning-results.md)第 1—4 节 |

## 3. 系统本身的评估（comment4）

**第三版 · S 任务流**（从 v19 出发，12 个任务、3 个任务族，3 次重放；不带记忆 → 带记忆）：

| 问题 | 结果 |
| --- | --- |
| 研究成果：带来多少提升 | 达标 36/36 → 36/36；最终加速比中位数 1.86× → 1.86× |
| 用了多长时间 | 单次研究循环时长中位数 31s → 14s；总耗时 1486s → 1064s |
| 花了多少 Token | 模型请求 27 → 6 次；输入 69,420 → 15,312，输出 27,693 → 6,172 |
| 云端模型成本 | 大模型请求 27 → 6 次，费用 USD 0.402 → USD 0.086；学习发生在任务流内部，费用已计入带记忆一侧 |
| 能否自我迭代并改进 | 新任务族首次出现时由分流器直接交给大模型，结果写入经验；其余任务带记忆时 30/30 次未调用模型（不带记忆 9/30）；经验条数每次重放 59 → 77 |

分流器对照（4 个新任务族的 T 任务，从 v19 出发，各 12 次）：分流关闭（先用本地 Qwen）达标 12/12、最终加速比中位数 2.11×、循环时长中位数 49s、费用 USD 0.047；分流开启（直接用 GPT）达标 12/12、2.18×、33s、USD 0.188；直接用 GPT 更快且首轮方案更优，每个新任务增加成本约 USD 0.012。

| 问题 | 第二版 · D 封存留出（v0 无经验 → v19） | 第一版 · C 最终留出（v0 → v6） |

| 用了多长时间 | 单次研究循环时长中位数 53s → 27s；总耗时 1782s → 669s | 84s → 50s；2000s → 1886s |

## 4. 架构边界与功能演进

- 专用决策模型对照（PRD §9 可选项）：已实现独立动作路由、模型路由与 OpenAI Decisions / TypeSafe Jev 适配器，支持 legacy 运行与显式启用 adaptive 的 native feedback 研究；四组合入口统一关闭初始经验分流，路由请求计入总预算。接口检查、历史回放与原生路由实验结果见[路由适配器](../design/action-model-routing.md)、[决策模型实验](../archive/decisions-experiments/README.md)与[路由研究入口](../research/native-routing/README.md)。
- 多 Agent 并行与跨领域扩展：首版主线聚焦单研究循环与可由程序自动验证的任务，确保经验库仅沉淀经过评测器验证的事实；开放式问答及多 Agent 协同留作后续扩展。
- 复验提示精简：第二版中复验未达标时全部复验程序留在提示词内，导致 B-05 单次输入升至 11.4k token（vs. v0 3.4k）；该项优化未纳入第二版冻结配置，已在第三版改为仅保留最佳复验程序。
- 过程结果与验收结果分离：对照页统一汇总最终独立验收结果，单次运行中的开发验证过程在对应运行页查看。
