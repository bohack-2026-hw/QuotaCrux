# RouteEvo 产品需求（Research Agent）

版本：v0.4；日期：2026-11-14。本文定义产品要求，具体评测参数见[评测入口](../evaluation/README.md)。

本文定义研究流程、功能目标和 RA 验收条件；[核心需求](core-requirements.md)定义通用运行、经验管理和版本规则。赛题依据见[原文与团队选择](competition-brief.md)，实现进度见[验收记录](acceptance-record.md)。

## 1. 产品目标与赛事边界

产品目标：在给定数据、工具和资源预算下，自主完成“规划—收集证据—提出假设—实验或分析—验证—修正”，交付经过验证的研究成果。

[赛题及补充说明](competition-brief.md)允许自由选择研究任务，使用一个 LLM 即可参赛。评估重点是研究方法、成果、成本和耗时。

首版用一个执行循环完成规划、分析、候选生成和结果检查。

主要评价同一研究任务中的改进和资源使用，跨任务经验另做对照。评测方法见[评测入口](../evaluation/README.md)，任务选型依据见[评测集调研](../archive/benchmark-survey.md)。

首版的 Qwen/GPT 配置见[实现决定](../archive/initial-implementation-decisions.md)；实际实验使用的模型在各批次协议中登记。

### 成功标准

- 每个主要实验有执行前记录的假设、证据和验证方法。
- 实际反馈能够改变下一步研究行动，而非按预写顺序执行全部实验。
- 最佳方案经过固定评价，研究结论引用实际结果，全部资源消耗可追踪。
- 在干净环境中按交付入口能够重跑方案与评价。

## 2. 最小研究任务

首版任务为已正确的 Python 分组聚合程序：按 key 分组，计算数量与整数求和，再按 key 升序输出。研究目标是保持正确性，在运行额度内改善处理性能。只允许修改指定程序范围，评测器与参考输出独立保存。

| 项目 | 首版软件性能任务 |
| --- | --- |
| 输入 | 初始实现、开发数据、语义约束与固定评价方式 |
| 收集证据 | 正确性结果、耗时分布、程序热点、输入特点 |
| 研究动作 | 调整计算方式、减少重复处理、修改局部实现 |
| 验证 | 独立正确性检查与一致环境下的性能测量；最终测试不向研究循环公开 |
| 最终成果 | 最佳已验证程序、性能报告和复现入口 |

已实现的首版任务包、A/B/C 划分和测量次数按[开工决策](../archive/initial-implementation-decisions.md)执行。新评测优先考虑 ALE-Bench 的单任务优化，AlgoTune 与 KernelBench 为备选；接入状态与资源依据见调研。表格分类与理论研究仍是企业方提供的可选场景，不列入当前实现。

## 3. 用户输入与最终交付

用户提供研究问题、初始数据或程序、目标与质量约束、可用工具、允许修改范围和预算。目标与评价方式在开始前固定。

任务结束后交付：

- 最佳已验证方案及其代码、参数和依赖信息；没有可行方案时明确标记。
- 初始基线、开发验证和最终评价结果，以及实际提升或退化。
- 证据、假设、实验、失败尝试及结论之间的关联记录。
- 全部 Token、模型费用、工具时长和总运行时间。
- 从固定输入重跑方案的入口、环境和随机种子（适用时）。

交付可运行的方案和报告；未见改善时记录“没有验证出改进”。

## 4. 研究流程

1. **理解与规划：**确认目标、限制和预算，形成简短的研究计划及首次测量安排。
2. **建立基线：**在固定条件下运行初始方案，保存可比较的质量和性能结果。
3. **收集证据：**使用工具观察数据或程序，只将相关统计、片段和结果交给模型。
4. **提出假设：**记录预期改善的原因、支持证据、拟采取的修改和能推翻该假设的结果。
5. **运行实验：**生成候选，执行质量检查与任务评价，记录所有资源消耗。
6. **验证与修正：**将假设标记为得到支持、被反驳或证据不足，决定继续、补证据、换方向或结束。
7. **最终交付：**选择最佳已验证候选，进行独立最终评价，导出方案、记录与复现材料。

例如，在软件任务中发现重复计算后，系统可以假设预计算会降低耗时；若测试发现语义变化，必须修正或放弃该候选。

## 5. 新增功能需求

| 编号 | 功能 | 具体要求 |
| --- | --- | --- |
| RA-01 | 研究任务定义 | 关联研究问题、目标、基线、允许修改范围、工具和预算 |
| RA-02 | 证据管理 | 每条关键观察关联工具输出或评价记录，区分测得事实与模型解释 |
| RA-03 | 假设与实验 | 在执行前保存假设、依据、操作及验证方法；实验结束后更新状态 |
| RA-04 | 反馈驱动调度 | 根据结果、已尝试方向和剩余预算选择下一行动，记录选择依据 |
| RA-05 | 候选比较 | 基于固定质量约束和比较规则保留最佳候选，失败或退化候选可追溯 |
| RA-06 | 最终独立评价 | 最终验收数据或测试不参与研究过程的方案选择，保存未挑选的真实结果 |
| RA-07 | 成果复现 | 导出最佳方案、环境、固定输入标识、执行入口、实验账本和评价结果 |
| RA-08 | 系统对照 | 比较固定预算下反馈迭代与独立尝试的研究效果；模型调度和跨任务经验分别作为扩展对照 |

RA-04 需要一个具体案例，说明实验反馈怎样改变了下一步行动。

## 6. 预算与模型使用

程序负责检查预算、约束可调用工具并记录账本；LLM 在允许范围内选择研究行动。预算覆盖规划、候选生成、失败修复、经验处理及额外决策调用。

降本优先来自：避免本任务内重复实验、依据验证反馈选择下一步、使用工具计算统计、控制输入上下文，以及在没有足够资源完成验证时停止发起新实验。跨任务复用的收益另行对照。

专用决策模型是可选增强，适合承担候选行动选择、经验相关性判断或升级时机判断；复杂假设生成与诊断仍由生成模型承担。只有全流程对照显示收益时才纳入默认流程。

分别记录两条模型路径的结果和费用，未执行的路径记为未知。暂不设金额上限；请求数、候选数和总时长仍有上限，决策 API 的调用也计入。

持续优化评测在达到阶段目标后仍可继续改进，直到模型主动结束或预算耗尽。各批次提前确定时长、请求数和候选数，具体设置见[正式协议](../research/native-formal-20261114/protocol.md)。

## 7. 本任务研究状态与最终评价隔离

当前研究中的观察、假设、候选和验证记录用于持续迭代。无跨任务经验的 `v0` 仍保留本次研究状态。主线各轮研究 从相同初始条件独立开始，不依赖先完成其他题目。

| 层次 | 数据划分与用途 |
| --- | --- |
| 主线：单个研究任务内部 | 开发输入和反馈用于修正候选；冻结最佳方案后独立最终评价，最终结果不能返回研究循环重新选方案 |
| 主线：多轮独立研究 | 不读取其他轮研究 的经验或产物；固定预算比较反馈迭代与独立尝试，并报告全部重复 |
| 可选：跨任务迁移 | A 批用于积累经验；B 批开发对照；C/D 按对应协议封存至配置冻结后的验收，使用冻结快照且不写入持久经验库 |

跨任务实验记录复用的策略或程序、来源、适用条件、收益和成本。

软件性能任务采用独立的正确性与性能验收输入；开发概况、开发验证与最终验收的边界按[开工决策](../archive/initial-implementation-decisions.md)执行。

## 9. 评价方案

评价分为任务成果和 Agent 系统效果两层：

| 对照或指标 | 回答的问题 |
| --- | --- |
| 初始任务基线与最终方案 | 实际研究产物改善了多少，是否满足质量约束 |
| 同预算反馈迭代与独立尝试 | 本次研究利用前序结果，是否优于互不传递反馈的多次尝试 |
| 最佳开发结果随实际耗时、Token、费用变化 | 后续实验是否继续改进，改善发生在什么时候、代价是多少 |
| 全部 Token、费用、耗时与实验记录 | 为取得成果付出了什么代价，失败尝试是否完整计入 |
| 可选的生成模型调度与决策模型调度 | 专用决策层是否减少总开销，是否引入误判与额外实验 |
| 可选的无历史经验与有历史经验 | 跨任务复用是否改善成果或效率，学习成本是多少 |

反馈对照首轮固定同一生成模型、工具、数据划分、初始方案与预算，唯一登记的差异是候选之间能否传递本次研究反馈与产物。独立尝试组由外部评测器选最佳候选，不把得分回传给下一次尝试。多模型调度另行实验，避免同时改变模型能力与信息条件。

过程曲线展示每次验证后的最佳开发指标，最终报告同时给出独立测试结果。预算、重复次数和停止规则在运行前确定，见[评测规则](../evaluation/README.md)。

性能任务用相同测量环境、输入和预先约定的重复方法比较。资源限制与验收方法在对照前冻结。

## 10. 方向验收

| 编号 | 验收条件 |
| --- | --- |
| RA-AC-01 | 研究问题、目标、约束、预算和基线在开始前确定并可复现 |
| RA-AC-02 | 关键实验执行前记录假设和验证方法，结论引用实际证据 |
| RA-AC-03 | 至少有一个能查到记录的反馈驱动案例，说明实际结果如何改变下一步；不要求人为制造失败 |
| RA-AC-04 | 错误、退化或证据不足的结果被正确记录，不能自动写成假设成立 |
| RA-AC-05 | 最终候选经过独立最终评价，通过与未通过均如实报告，最终数据未用于该候选的调优 |
| RA-AC-06 | 总成本覆盖完整研究过程；预算不足时正确结束并保留最佳已验证产物或无结果状态 |
| RA-AC-07 | 交付材料能从固定初始输入重跑最佳方案与评价；来源运行和环境可查 |
| RA-AC-08 | 提供固定预算下反馈迭代与独立尝试的完整对照、过程曲线及独立最终结果；若另主张历史经验或路由有效，提供相应独立对照 |

验收报告展示全部正式实验，包括没有改善的运行。

## 11. 演示与交付

演示依次展示研究问题、预算、初始结果、一次根据反馈修改方案的过程，以及最终方案和用量记录。

现场运行选择耗时合适的任务；较长实验展示已保存的记录，并标明运行时间。

除代码、PPT 和项目说明外，交付研究任务定义、最佳方案、实验账本、最终评价、资源报告和复现说明；使用跨任务经验的实验另附冻结快照。

按现有赛事说明，材料于 2026 年 11 月 15 日 08:00 前提交，当日上午现场展示，时区为 Asia/Shanghai。

## 12. 实现顺序与可后置内容

1. 在共用 M1 上完成 RA-01—RA-03，连通研究问题、基线、证据与实验。
2. 完成 RA-04—RA-07，让反馈影响下一步，并可独立验证和复现最终方案。
3. 完成 RA-08 的反馈利用对照与过程曲线，完善展示；模型调度与跨任务经验分别作为后续扩展验证。

首版用已有 Qwen 服务完成软件优化任务及其对照评测，其他能力后续再做。
