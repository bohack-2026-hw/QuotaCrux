# Research Agent 验收对照

依据：[Research Agent 主线 PRD](research-agent-track-prd.md) 第 5 节（RA-01—RA-08）与第 10 节（RA-AC-01—RA-AC-08）、[补充说明](research-agent-clarifications.md) comment4。数字均来自[实验结果](results.md)，样例来自[研究成果样例](research/)，都由运行记录生成。

## 1. 功能需求

| 编号 | 实现 | 在哪里看 |
| --- | --- | --- |
| RA-01 研究任务定义 | 任务包冻结研究问题（契约）、初始程序、开发/最终数据、目标；运行创建时冻结预算、工具、模型与评测器，写入配置指纹 | 运行页“研究任务 · 运行开始前固定”；研究记录“研究任务”节；`backend/tasks/lock.json` |
| RA-02 证据管理 | 取证工具（cProfile）与每次评测都有记录 ID；评测反馈只给测得事实（状态、加速比、失败类别、公开反例）；模型解释单独标为“未验证” | 运行页决策账本；经验卡片“测得事实 / 模型解释”分栏 |
| RA-03 假设与实验 | 每个候选提交前，模型写下目的、预期结果和验证方法，并给出假设（未验证）；评测后由程序判定：支持、部分支持、反驳、未能检验 | 运行页“假设与实验”；研究记录同名表；结果第 4 节统计 |
| RA-04 反馈驱动调度 | 每步状态包含上一结果、已试方向、剩余预算；程序记录下一步决定及依据；连续未达标按固定规则升级到 GPT | 决策账本“→ 下一步”；升级步骤写明触发条件 |
| RA-05 候选比较 | 只有通过且全部样本快于基线的候选才能替换最佳；失败与退化候选保留代码和评测 | 运行页候选加速比条；`report.json` 的 `best_rule` |
| RA-06 最终独立评价 | 循环结束后冻结最佳候选，在隐藏最终数据上测一次；最终数据不进容器、不进检索、不回流 | 运行页第四个状态“最终测试达到目标”；研究记录“独立最终测试” |
| RA-07 成果复现 | `export-run --bundle` 导出研究记录、最佳程序、全部候选、原始模型调用、报告与复核脚本；`experiment.sh` 重跑整条流水线 | [研究成果样例](research/)；`reproduce.sh` |
| RA-08 系统对照 | 同一 Agent、同一配置，只换经验快照（v0 无经验 vs v6），B 开发对照与 C 最终留出各 6 任务 × 3 次，交替串行 | 对照页；[实验结果](results.md) 第 2、3 节 |

## 2. 验收条件

| 编号 | 证据 | 结论 |
| --- | --- | --- |
| RA-AC-01 问题、目标、约束、预算、基线事前确定且可复现 | 19 个任务包按哈希锁定；每次运行保存配置指纹（模型、提示词、动作模式、预算、评测器、沙箱镜像、检索规则）；基线在同一次评测中交替测得 | 满足 |
| RA-AC-02 关键实验有事前假设和验证方法，结论引用实际证据 | 78 次正式运行共 152 个候选，全部在提交前写下目的、预期结果与验证方法，其中 142 个另写了明确假设（10 个只写目的）；判定引用评测 ID（结果第 4 节） | 满足 |
| RA-AC-03 至少一个可核验的反馈驱动决策 | [A-01](research/run-20261113T161733-7c5a/README.md)：c1 实测 0.90×，假设被反驳 → Qwen 的 c2 针对 c1 变慢的原因改用 str key，但输出格式错误 → 按规则升级 → GPT 读到“表头格式错误”和 c1 的慢因，提出批量分行 + 单字典，1.45× 得到支持。统计上，后续假设中有 19/74 点名引用了同一运行的早先候选（下限） | 满足 |
| RA-AC-04 错误、退化、证据不足如实记录 | 判定由程序给出，不由模型自评：正式运行中被反驳 53 个、未能检验 16 个；[A-05](research/run-20261113T162613-8f0a/README.md) 三个假设全部被反驳，结论“无改进” | 满足 |
| RA-AC-05 最终独立评价，通过与未通过都报告 | [C-04 / v0](research/run-20261113T174641-8a40/README.md) 开发数据达标但最终测试有一个样本不快于基线，记为未达标；B、C 中共 3 次此类情况，两边都有 | 满足 |
| RA-AC-06 总成本覆盖完整过程，预算不足时正确结束 | 每次模型调用记录用量与估算费用，未知记“未知”不记 0；学习阶段成本单列；A-03、A-05 预算耗尽后交付初始程序、不再为总结调用模型 | 满足 |
| RA-AC-07 从固定输入重跑最佳方案与评价 | A-01 样例的 `reproduce.sh` 复核：最终数据正确、1.44×（记录值 1.4367×）；环境（沙箱镜像 ID、容器 Python 版本、Docker 服务信息、资源额度）随运行保存 | 满足 |
| RA-AC-08 主张经验有效时提供完整对照 | B、C 各 36 次运行全部计入，配置一致性检查通过；学习成本单列；不利结果（C 最终加速比中位数下降、B-05 反例）同样报告 | 满足 |

## 3. 系统本身的评估（comment4）

| 问题 | 回答（C 最终留出，v0 无经验 → v6 有经验） |
| --- | --- |
| 花了多少 Token | 输出 45,728 → 30,532；输入 151,880 → 232,044（经验进入提示词，单次请求更长） |
| 多长时间带来多少提升 | 18 次运行中 16 次达标（两边相同）；单次研究循环时长中位数 84 s → 50 s；最终加速比中位数 1.41× → 1.29× |
| 云端模型成本 | 升级到 GPT 11 → 5 次，费用 $0.372 → $0.292；学习阶段另计 $0.149 |
| 能否自我迭代并改进 | A 批学习 v0 → v6 共 13 条经验；读到经验后请求中位数 3 → 1、失败候选 6 → 1；两轮自我迭代演示（学习 → 自动发布 → 留出对照）实测 4.7 分钟走通 |

学到的是“更省的达标路径”，不是更高的性能上限：用过 GPT 的达标运行加速比中位数 1.49—1.53×，只用 Qwen 的 1.27—1.28×；经验让 Qwen 更常一次达标、更少升级，也就更早停在较小的加速比。追求上限需要修改终止条件。
