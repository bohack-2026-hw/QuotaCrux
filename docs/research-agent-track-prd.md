# RouteEvo Research Agent PRD

版本：v0.4；日期：2026-11-14；状态：已选赛道的开发主线；本次调整评测协议，新增对照尚待实现与执行。

团队已确认选择倍漾量化 Research Agent 赛道。本方案在[核心 PRD](shared-core-prd.md)上明确研究问题、证据与假设、实验选择、独立评价和成果复现，是当前开发与验收的主线。

## 1. 产品目标与赛事边界

产品目标：在给定数据、工具和资源预算下，自主完成“规划—收集证据—提出假设—实验或分析—验证—修正”，交付经过验证的研究成果。

按[企业赛题](https://tcnf5s7xd39g.feishu.cn/wiki/EpxXwbYkkieZrfk0QbRc7wWQnRc#doxcn2L75UoUOu4KCukBPrZHmxf)及团队提供的 [comment1—comment4 补充说明](research-agent-clarifications.md)，本地轻量模型可以忽略，仅使用一个 LLM 也可完成项目。研究任务可以自由选择，重点评估 Agent 如何做研究，以及其成本、效率、成果和迭代能力。补充原文与团队确认均保存在链接文档中。

首版采用一个研究执行循环。规划、分析、生成候选和审视结果是工作阶段，不要求实现成多个独立 Agent。

主线评价单个研究任务内的持续改进与资源效率，跨题目或跨 session 的经验积累作为扩展。具体对照、长时预算与实施差距见[单任务评测方案](research-evaluation-plan.md)，候选任务见[benchmark 调研](long-horizon-benchmarks.md)。

当前具体实现按[开工决策](implementation-decisions.md)：Qwen 常规执行，GPT-6.1 Sol（xhigh）升级诊断与候选生成。单 LLM 是赛题允许的下限，当前已选择两条模型路径。

### 成功标准

- 每个主要实验有事前记录的假设、证据和验证方法。
- 实际反馈能够改变下一步研究行动，而非按预写顺序执行全部实验。
- 最佳方案经过固定评价，研究结论引用实际结果，全部资源消耗可追踪。
- 在干净环境中按交付入口能够重跑方案与评价。

## 2. 最小研究任务

首版任务为已正确的 Python 分组聚合程序：按 key 分组，计算数量与整数求和，再按 key 升序输出。研究目标是保持正确性，在运行额度内改善处理性能。只允许修改指定程序范围，评测器与参考输出独立保存。

| 项目 | 首版软件性能任务 |
| --- | --- |
| 输入 | 初始实现、开发数据、语义约束与固定评价方式 |
| 收集证据 | 正确性结果、耗时分布、程序热点、输入特点 |
| 研究动作 | 调整计算方式、减少重复处理、修改局部实现 |
| 验证 | 独立正确性检查与一致环境下的性能测量；最终测试不向研究循环公开 |
| 最终成果 | 最佳已验证程序、性能报告和复现入口 |

已实现的首版任务包、A/B/C 划分和测量次数保留[开工决策](implementation-decisions.md)口径。新评测优先考虑 ALE-Bench 的单任务优化，AlgoTune 与 KernelBench 为备选；接入状态与资源依据见调研。表格分类与理论研究仍是企业方提供的可选场景，不列入当前实现。

## 3. 用户输入与最终交付

用户提供研究问题、初始数据或程序、目标与质量约束、可用工具、允许修改范围和预算。目标与评价方式在开始前固定。

任务结束后交付：

- 最佳已验证方案及其代码、参数和依赖信息；没有可行方案时明确标记。
- 初始基线、开发验证和最终评价结果，以及实际提升或退化。
- 证据、假设、实验、失败尝试及结论之间的关联记录。
- 全部 Token、模型费用、工具时长和总运行时间。
- 从固定输入重跑方案的入口、环境和随机种子（适用时）。

一份文字报告不能代替可执行成果；“没有验证出改进”可以作为真实研究结论，但不能包装成已经提升。

## 4. 研究流程

1. **理解与规划：**确认目标、限制和预算，形成简短的研究计划及首次测量安排。
2. **建立基线：**在固定条件下运行初始方案，保存可比较的质量和性能结果。
3. **收集证据：**使用工具观察数据或程序，只将相关统计、片段和结果交给模型。
4. **提出假设：**记录预期改善的原因、支持证据、拟采取的修改和能推翻该假设的结果。
5. **运行实验：**生成候选，执行质量检查与任务评价，记录所有资源消耗。
6. **验证与修正：**将假设标记为得到支持、被反驳或证据不足，决定继续、补证据、换方向或结束。
7. **最终交付：**选择最佳已验证候选，进行独立最终评价，导出方案、记录与复现材料。

例如，在软件任务中发现重复计算后，系统可以假设预计算会降低耗时；若测试发现语义变化，必须修正或放弃该候选。此流程说明要支持的研究行为，不能预设每次实验必然成功。

| RA-02 | 证据管理 | 每条关键观察关联工具输出或评价记录，区分测得事实与模型解释 |

## 6. 预算与模型使用

程序负责检查预算、约束可调用工具并记录账本；LLM 在允许范围内选择研究行动。预算覆盖规划、候选生成、失败修复、经验处理及额外决策调用。

降本优先来自：避免本任务内重复实验、依据验证反馈选择下一步、使用工具计算统计、控制输入上下文，以及在没有足够资源完成验证时停止发起新实验。跨任务复用的收益另行对照。

专用决策模型是可选增强，适合承担候选行动选择、经验相关性判断或升级时机判断；复杂假设生成与诊断仍由生成模型承担。只有全流程对照显示收益时才纳入默认流程。

两条模型路径分别记录具体任务与配置下的真实结果。没有执行的路径保持未知，不能仅按总体成功率认定哪个模型更优。暂不设金额上限，仍保留有限的请求、候选与时长额度；托管决策 API 若后续接入，同样计入云端模型成本。

长时评测需要同时调整墙钟、请求、候选额度与停止行为。当前默认仍为 300 秒、6 请求、4 候选，达标即停；新协议把性能阈值作为过程里程碑，在预算内允许继续改进。该行为尚待实现，不能仅提高时长参数就宣称已完成长时评测。

## 7. 本任务研究状态与最终评价隔离

当前研究中的观察、假设、候选和验证记录用于持续迭代。无跨任务经验的 `v0` 仍保留本次研究状态。主线各 episode 从相同初始条件独立开始，不依赖先完成其他题目。

| 层次 | 数据划分与用途 |
| --- | --- |
| 主线：单个研究任务内部 | 开发输入和反馈用于修正候选；冻结最佳方案后独立最终评价，最终结果不能返回研究循环重新选方案 |
| 主线：多个独立 episode | 不读取其他 episode 的经验或产物；固定预算比较反馈迭代与独立尝试，并报告全部重复 |
| 可选：跨任务迁移 | A 批用于积累经验；B 批开发对照；C/D 按对应协议封存至配置冻结后的验收，使用冻结快照且不写入持久经验库 |

需要主张迁移能力时，记录有效策略、失败方向、收益、代价及适用条件，并关联来源实验。此时再使用既有跨任务划分，不能把完整程序复用直接解释为新问题上的研究能力。

软件性能任务采用独立的正确性与性能验收输入；开发画像、开发验证与最终验收的边界按[开工决策](implementation-decisions.md)执行。

## 9. 评价方案

评价分为任务成果和 Agent 系统效果两层：

| 对照或指标 | 回答的问题 |
| --- | --- |
| 初始任务基线与最终方案 | 实际研究产物改善了多少，是否满足质量约束 |
| 同预算反馈迭代与独立尝试 | 本次研究利用前序结果，是否优于互不传递反馈的多次尝试 |
| 最佳开发结果随墙钟、Token、费用变化 | 后续实验是否继续改进，改善发生在什么时候、代价是多少 |
| 全部 Token、费用、耗时与实验记录 | 为取得成果付出了什么代价，失败尝试是否完整计入 |
| 可选的生成模型调度与决策模型调度 | 专用决策层是否减少总开销，是否引入误判与额外实验 |
| 可选的无历史经验与有历史经验 | 跨任务复用是否改善成果或效率，学习成本是多少 |

反馈对照首轮固定同一生成模型、工具、数据划分、初始方案与预算，唯一登记的差异是候选之间能否传递本次研究反馈与产物。独立尝试组由外部评测器选最佳候选，不把得分回传给下一次尝试。多模型调度另行实验，避免同时改变模型能力与信息条件。

过程曲线展示当时已完成验证的最佳开发指标，最终结论同时报告独立验收结果。新方案先做 15 分钟 pilot，再冻结 30 分钟正式预算；具体数量、额度、计时边界和停止规则见[评测方案](research-evaluation-plan.md)。

性能任务用相同测量环境、输入和预先约定的重复方法比较。资源限制与验收口径在对照前冻结。

## 10. 方向验收

| 编号 | 验收条件 |
| --- | --- |
| RA-AC-01 | 研究问题、目标、约束、预算和基线在开始前确定并可复现 |
| RA-AC-02 | 关键实验具有事前假设和验证方法，结论引用实际证据 |
| RA-AC-03 | 至少有一个可核验的反馈驱动决策案例，说明实际结果如何改变下一步；不要求人为制造失败 |
| RA-AC-04 | 错误、退化或证据不足的结果被正确记录，不能自动写成假设成立 |
| RA-AC-05 | 最终候选经过独立最终评价，通过与未通过均如实报告，最终数据未用于该候选的调优 |
| RA-AC-06 | 总成本覆盖完整研究过程；预算不足时正确结束并保留最佳已验证产物或无结果状态 |
| RA-AC-07 | 交付材料能从固定初始输入重跑最佳方案与评价；来源运行和环境可查 |
| RA-AC-08 | 提供固定预算下反馈迭代与独立尝试的完整对照、过程曲线及独立最终结果；若另主张历史经验或路由有效，提供相应独立对照 |

验收可同时包含有改进和无改进案例；项目不能只展示挑选出的成功实验。是否具备有竞争力的研究效果，根据正式任务上的结果判断。

## 11. 演示与交付

建议演示从研究问题、预算和基线开始，展示一条真实的证据—假设—实验—修正链，再交付最佳方案、独立结果和资源账本。重点保留每次决策的依据，不将界面变成只有模型对话的聊天窗口。

现场任务按实际资源选择规模。耗时较长的完整实验可在材料中提供可复现记录，现场演示内容和既有记录明确区分；不将历史实验伪装成现场执行。

除代码、PPT 和项目说明外，交付研究任务定义、最佳方案、实验账本、最终评价、资源报告和复现说明；使用跨任务经验的实验另附冻结快照。

按现有赛事说明，材料于 2026 年 11 月 15 日 08:00 前提交，当日上午现场展示，时区为 Asia/Shanghai。
