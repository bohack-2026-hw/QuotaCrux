# RouteEvo Research Agent 方向增量 PRD

版本：v0.2；日期：2026-11-13；状态：备选方向草案。

本方案以[共用核心 PRD](shared-core-prd.md)为基础。选定倍漾量化赛道后，重点补齐研究问题、证据与假设、实验选择、独立评价和成果复现。

## 1. 产品目标与赛事边界

产品目标：在给定数据、工具和资源预算下，自主完成“规划—收集证据—提出假设—实验或分析—验证—修正”，交付经过验证的研究成果。

按[企业赛题](https://tcnf5s7xd39g.feishu.cn/wiki/EpxXwbYkkieZrfk0QbRc7wWQnRc#doxcn2L75UoUOu4KCukBPrZHmxf)及团队提供的 comment1—comment4 补充说明，本地轻量模型可以忽略，仅使用一个 LLM 也可完成项目。研究任务可以自由选择，重点评估 Agent 如何做研究，以及其成本、效率、成果和迭代能力。

首版采用一个研究执行循环。规划、分析、生成候选和审视结果是工作阶段，不要求实现成多个独立 Agent。

当前具体实现按[开工决策](implementation-decisions.md)：Qwen 常规执行，GPT-6.1 Sol（xhigh）升级诊断与候选生成。单 LLM 是赛题允许的下限，当前已选择两条模型路径。

### 成功标准

- 每个主要实验有事前记录的假设、证据和验证方法。
- 实际反馈能够改变下一步研究行动，而非按预写顺序执行全部实验。
- 最佳方案经过固定评价，研究结论引用实际结果，全部资源消耗可追踪。
- 在干净环境中按交付入口能够重跑方案与评价。

## 2. 最小研究任务

默认沿用共用核心的小型 Python 数据处理程序，研究目标是：保持正确性，在预算内改善性能。只允许修改指定程序范围，评测器与参考输出独立保存。

| 项目 | 默认软件性能任务 | 可替代的表格分类任务 |
| --- | --- | --- |
| 输入 | 初始实现、数据、正确性测试、基准测量程序 | 带标签的数据、目标指标、固定数据划分 |
| 收集证据 | 正确性结果、耗时分布、程序热点、输入特点 | 缺失值、类别分布、基线表现、错误类型 |
| 研究动作 | 调整计算方式、减少重复处理、修改局部实现 | 清洗、构造特征、选择模型、调参 |
| 验证 | 独立正确性检查与一致环境下的性能测量 | 开发验证指标与独立最终测试结果 |
| 最终成果 | 最佳已验证程序、性能报告和复现入口 | 最佳处理及训练流程、模型、评价与复现入口 |

正式实现时二选一。表格任务需要补充专用训练与数据划分工具；若继续软件性能任务，则优先复用已有执行器和评测器。

## 3. 用户输入与最终交付

用户提供研究问题、初始数据或程序、目标与质量约束、可用工具、允许修改范围和预算。目标与评价方式在开始前固定。

任务结束后交付：

- 最佳已验证方案及其代码、参数和依赖信息；没有可行方案时明确标记。
- 初始基线、开发验证和最终评价结果，以及实际提升或退化。
- 证据、假设、实验、失败尝试及结论之间的关联记录。
- 全部 Token、模型费用、工具时长和总运行时间。
- 从固定输入重跑方案的入口、环境和随机种子（适用时）。

一份文字报告不能代替可执行成果；“没有验证出改进”可以作为真实研究结论，但不能包装成已经提升。

## 4. 研究流程

1. **理解与规划：**确认目标、限制和预算，形成简短的研究计划及首次测量安排。
2. **建立基线：**在固定条件下运行初始方案，保存可比较的质量和性能结果。
3. **收集证据：**使用工具观察数据或程序，只将相关统计、片段和结果交给模型。
4. **提出假设：**记录预期改善的原因、支持证据、拟采取的修改和能推翻该假设的结果。
5. **运行实验：**生成候选，执行质量检查与任务评价，记录所有资源消耗。
6. **验证与修正：**将假设标记为得到支持、被反驳或证据不足，决定继续、补证据、换方向或结束。
7. **最终交付：**选择最佳已验证候选，进行独立最终评价，导出方案、记录与复现材料。

例如，在软件任务中发现重复计算后，系统可以假设预计算会降低耗时；若测试发现语义变化，必须修正或放弃该候选。此流程说明要支持的研究行为，不能预设每次实验必然成功。

## 5. 新增功能需求

| 编号 | 功能 | 具体要求 |
| --- | --- | --- |
| RA-01 | 研究任务定义 | 关联研究问题、目标、基线、允许修改范围、工具和预算 |
| RA-02 | 证据管理 | 每条关键观察关联工具输出或评价记录，区分测得事实与模型解释 |
| RA-03 | 假设与实验 | 在执行前保存假设、依据、操作及验证方法；实验结束后更新状态 |
| RA-04 | 反馈驱动调度 | 根据结果、已尝试方向和剩余预算选择下一行动，记录选择依据 |
| RA-05 | 候选比较 | 基于固定质量约束和比较规则保留最佳候选，失败或退化候选可追溯 |
| RA-06 | 最终独立评价 | 最终验收数据或测试不参与研究过程的方案选择，保存未挑选的真实结果 |
| RA-07 | 成果复现 | 导出最佳方案、环境、固定输入标识、执行入口、实验账本和评价结果 |
| RA-08 | 系统对照 | 比较同一 Agent 有无历史经验时的研究效果，并支持后续决策模型对照 |

如果只是轮流尝试若干预设选项再选最高分，尚不足以证明 RA-04。需要能够指出某个实际反馈如何影响后续的证据收集、实验选择、修正或停止。

## 6. 预算与模型使用

程序负责检查预算、约束可调用工具并记录账本；LLM 在允许范围内选择研究行动。预算覆盖规划、候选生成、失败修复、经验处理及额外决策调用。

首版的降本优先来自：避免重复实验、复用已验证经验、使用工具计算统计、控制输入上下文，以及在没有足够资源完成验证时停止发起新实验。

专用决策模型是可选增强，适合承担候选行动选择、经验相关性判断或升级时机判断；复杂假设生成与诊断仍由生成模型承担。只有全流程对照显示收益时才纳入默认流程。

两条模型路径分别记录具体任务与配置下的真实结果。没有执行的路径保持未知，不能仅按总体成功率认定哪个模型更优。暂不设金额上限，仍保留有限的请求、候选与时长额度；托管决策 API 若后续接入，同样计入云端模型成本。

## 7. 经验与两层评测隔离

当前研究中的观察记录用于持续迭代。跨研究任务的经验记录有效策略、失败方向、实际收益、代价及适用条件，并关联来源实验。

| 层次 | 数据划分与用途 |
| --- | --- |
| 单个研究任务内部 | 开发输入和验证结果用于修正候选；最终测试只用于验收，不能据其结果重新调优后仍将其作为独立测试 |
| 多个研究任务之间 | A 批用于积累经验；B 批进行开发对照；C 批封存至配置冻结后的最终验收，B/C 均使用冻结快照且不写入持久经验库 |

B 批任务内部仍可以根据自己的开发验证结果迭代，这是研究流程的一部分；其独立最终测试与跨任务记忆隔离保持不变。

默认软件性能任务采用独立的正确性与性能验收输入；若换成表格分类，使用训练、验证、最终测试划分，预处理参数只从允许的训练数据拟合。[评估与数据隔离参考](https://scikit-learn.org/stable/modules/cross_validation.html)

## 8. 数据与界面增量

在 Run、Step、Evaluation 和 Experience 上补充关系，首版可使用结构化附属字段保存，不要求新增独立服务。

| 增量信息 | 内容 |
| --- | --- |
| 研究上下文 | 研究问题、基线引用、主要指标、允许动作和当前最佳候选 |
| 证据 | 工具或评价记录引用、观察内容、事实或解释标识 |
| 假设 | 命题、支持证据、预期结果、验证方法与当前状态 |
| 实验 | 对应假设、父候选、本次改动、执行参数、结果和成本 |
| 研究决策 | 继续、补证据、换方向或停止，以及相关反馈引用 |
| 最终成果 | 最佳候选、最终评价、复现入口和剩余问题 |

共用运行页面增加研究阶段、假设与实验列表、累计预算和最佳候选区域。对照页面同时展示基线、过程中的最佳验证结果及最终验收结果，区分它们的用途。

## 9. 评价方案

评价分为任务成果和 Agent 系统效果两层：

| 对照或指标 | 回答的问题 |
| --- | --- |
| 初始任务基线与最终方案 | 实际研究产物改善了多少，是否满足质量约束 |
| 同一 Agent 无历史经验与有历史经验 | 相同研究任务和预算下，经验是否改善研究结果或效率 |
| 全部 Token、费用、耗时与实验记录 | 为取得成果付出了什么代价，失败尝试是否完整计入 |
| 可选的生成模型调度与决策模型调度 | 专用决策层是否减少总开销，是否引入误判与额外实验 |

同一 Agent 的对照固定模型、指令、工具、数据划分、初始方案与预算，允许各自依据反馈选择不同实验。过程曲线可展示累计 Token 或时间对应的最佳开发验证指标，最终效果结论同时报告独立验收结果。

性能任务用相同测量环境、输入和预先约定的重复方法比较；分类任务用同一指标与划分比较。不通过改变资源限制或验收口径制造改进。

## 10. 方向验收

| 编号 | 验收条件 |
| --- | --- |
| RA-AC-01 | 研究问题、目标、约束、预算和基线在开始前确定并可复现 |
| RA-AC-02 | 关键实验具有事前假设和验证方法，结论引用实际证据 |
| RA-AC-03 | 至少有一个可核验的反馈驱动决策案例，说明实际结果如何改变下一步；不要求人为制造失败 |
| RA-AC-04 | 错误、退化或证据不足的结果被正确记录，不能自动写成假设成立 |
| RA-AC-05 | 最终候选经过独立最终评价，通过与未通过均如实报告，最终数据未用于该候选的调优 |
| RA-AC-06 | 总成本覆盖完整研究过程；预算不足时正确结束并保留最佳已验证产物或无结果状态 |
| RA-AC-07 | 交付材料能从固定初始输入重跑最佳方案与评价；来源运行和环境可查 |
| RA-AC-08 | 若主张历史经验有效，提供相同预算下无经验与有经验的完整对照 |

验收可同时包含有改进和无改进案例；项目不能只展示挑选出的成功实验。是否具备有竞争力的研究效果，根据正式任务上的结果判断。

## 11. 演示与交付

建议演示从研究问题、预算和基线开始，展示一条真实的证据—假设—实验—修正链，再交付最佳方案、独立结果和资源账本。重点保留每次决策的依据，不将界面变成只有模型对话的聊天窗口。

现场任务按实际资源选择规模。耗时较长的完整实验可在材料中提供可复现记录，现场演示内容和既有记录明确区分；不将历史实验伪装成现场执行。

除代码、PPT 和项目说明外，交付研究任务定义、最佳方案、实验账本、最终评价、资源报告、经验快照及复现说明。

## 12. 实现顺序与可后置内容

1. 在共用 M1 上完成 RA-01—RA-03，连通研究问题、基线、证据与实验。
2. 完成 RA-04—RA-07，让反馈影响下一步，并可独立验证和复现最终方案。
3. 接入共用 M2、M3 与 RA-08，验证执行经验对研究过程的增益，完善展示。

第一版不同时开发软件优化与表格建模两个任务包。接入团队已有 Qwen 服务即可；新增本地模型部署、多 Agent、专用决策 API、开放式文献检索和跨领域研究能力均可后置，它们不能替代已经定义的研究闭环与效果证据。
