# 第二轮 CPU 开发预实验：调用前冻结的协议

日期：2026-11-14。本轮检查任务概况、分析状态传递和计时修正后的实际行为。新代码和本协议先签名提交、推送，再调用模型；运行 manifest 记录确切提交。

## 问题与修正

- 第一轮卷积概况仅有 `size=1000`，真实两个输入分别为长度 30000、8000 的 float64 数组，full 输出长度 37999。新概况直接读取开发输入的结构，契约写明输出类型和相对 L2 误差阈值 1e-6。概况参与不可变任务身份；旧包和第一轮结果保持原样。
- 第一轮 feedback 的 `analyze` 只把目的摘要放入下一请求，丢失分析内容和假设。本轮保留两项，independent 继续只看到初始程序和剩余预算。
- 使用已有 v5 提示，完整动作示例包含三个必填公共字段，并明确严格计时门槛。第一轮为 v4。本轮不自动补全模型漏填的字段。
- 计时使用独立候选容器、固定性能核 CPU 2、单线程，预热 3 次、正式测量 5 次。所有输出，包括预热输出，都经独立裁判检查。每次仍重新创建候选全局变量与输入对象。

## 校准依据

无模型调用，仅使用同一冻结开发输入、上游初始程序，以及在 solve 后增加 3 ms sleep 的控制程序。逐例原始函数时间、初始化时间、测量次序、镜像和硬件记录均已保留。

| 配置 | 自比中位加速比，3 组 | 自比误入选 | 组内极差/中位数的中位数 | 首点相对后续点中位数偏差 |
| --- | --- | ---: | ---: | ---: |
| 不绑核，预热 1 次 | 1.0139 / 1.0106 / 1.0900 | 0 | 10.98% | 8.44% |
| CPU 2，预热 1 次 | 0.9856 / 0.9950 / 0.9890 | 0 | 9.56% | 7.13% |
| CPU 2，预热 3 次 | 0.9945 / 1.0088 / 0.9945 | 0 | 8.85% | 2.31% |

两批正控制均通过严格提升门槛（4.3193× / 4.3639×），负控制均未入选（0.2283× / 0.2270×）。实际容器 affinity 探针分别返回 3 次、5 次 `[2]`。两批分别耗时约 34.35 秒和 20.33 秒。

[预热 1 次完整结果](calibration-w1.json)使用原 scientific 镜像；[预热 3 次完整结果](calibration-w3.json)使用支持可配置预热的新镜像。两者镜像 ID、源码哈希均逐批记录，开发输入哈希相同。校准在固定正式代码前进行，两批使用不同镜像。固定 CPU 与增加预热减小了观察到的系统偏移，组内仍有约 9% 波动，本轮保留 `max(candidate) < min(baseline)`；约 10% 的改善可能被噪声掩盖。

## 固定实验条件

- ALE-Bench `ahc026`：`ale-bench-ahc026-smoke-2960ce864b`；AlgoTune `convolve_1d`：`algotune-convolve_1d-smoke-eeb3cd9d83`。
- 每题 2 个开发用例、3 个封存最终用例；本轮只做开发评测。卷积 `size=1000, seed=1729`，与第一轮开发输入完全相同。
- AIPing **Qwen3.8-27B**，固定 small，无模型升级；eval 模式，空经验快照 `v0`，不积累跨任务/session 经验。
- 每轮研究：最多 900 秒、20 次请求、10 个候选；请求超时 120 秒。允许模型主动 finish。两组预算上限相同，实际支出如实记录。
- 4 轮研究 全部串行：ALE feedback → independent；AlgoTune independent → feedback。每组 1 次。
- `MeasureConfig`：`cpus=1.0, cpuset_cpus="2", memory="1g", function_warmups=3, repeats=5`，其余默认项记录于 manifest。ALE 按原生 raw score 选优；AlgoTune 正确性、严格区间比较和 1.10× 目标不变。
- 本地路由 agent 已交接 CPU/Docker/Qwen 窗口，远端协作记录见仓库 issue #1。实验结束前不并发运行其他容器计时或真实模型测试。

## 开始前确定的报告指标

1. 请求数、各类动作数、格式/动作错误及原因；检查必填字段问题是否减少。
2. 提出/通过候选数、候选/请求比、按代码结构去重后的候选数；检查分析是否接成实际实验。
3. 最终保留方案的开发可行性、ALE 原始得分或 AlgoTune 稳定加速比，以及全部候选的原始速度测量和最佳值轨迹。
4. 停止原因、实际耗时、模型等待、评测时间、输入/输出 Token、API 标价估算。
5. 核对 feedback 下一请求保留分析、independent 原始请求没有历史或其他候选泄漏，确认 final 未评测。

结果无论正负均保留全部四轮与候选。与第一轮相比，提示、概况、状态传递、绑核和预热同时发生变化，因此前后差异只用于修复后的过程诊断。本轮每题每组运行一次，仅评测开发集。

## 执行

在 `backend/` 使用本轮冻结代码与任务包：

```bash
.venv/bin/python ../docs/research/native-r2-20261114/run_pilot.py \
  ale-bench-ahc026-smoke-2960ce864b algotune-convolve_1d-smoke-eeb3cd9d83 \
  --calibration ../docs/research/native-r2-20261114/calibration-w3.json \
  --pricing /path/to/qwen-price.json --out var/new-native-r2-pilot
```

脚本在首次模型请求前写出 manifest，并核对定价模型、校准所用开发输入和候选镜像。`--dotenv` 可指定本机凭据文件，凭据不进入产物。估算使用运行前获取的 AIPing 价格快照，不作为账户账单。
