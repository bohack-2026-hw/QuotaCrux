# 一小时双机补充实验

用户将补实验范围缩为约一小时，允许 laptop 与 desktop 并行。本批只比较 ahc026 上四种模型使用策略，各主机完整执行四组一次，共八轮；不增加反馈模式或新任务。

## 冻结条件

- 执行源码：`912b20a4cfeb51af9c36d0679b23f0990abe862f`，即今天路由短批的版本。此版本 Python 包名仍为 `routeevo`。产品当前 checkout 的界面修改不进入实验。
- 四组：`fixed_small`、`fixed_large`、`adaptive_rule`、`action_decisions`。全部使用 feedback、eval、空 v0，禁用初始经验路由，每轮新建 run，不写回经验。
- small：托管 Qwen3.8-27B，thinking=false，max_output_tokens=8192；large：gpt-6.1-sol，xhigh，max_output_tokens=32000；动作路由：Decisions gpt-6-luna。端点与公开参数继承当天短批冻结配置。
- 每轮上限：研究循环 360 秒、全部模型 HTTP 请求 20 次、候选 10 个；允许系统主动结束。启动与 final 单列。总计划最多 160 个模型请求；每台串行、双机最多两个在途请求。
- 数据：继承原 ahc026 的同一 5 dev / 15 final 包。每轮按 dev 选定候选，再执行独立 final。旧 final 已在之前研究中观察，因此这是既有任务上的补充对照，不是全新未见任务确认。
- 初始程序 dev 得分必须为 44120。两台分别校验通过后才启动付费请求。final 不用于环境校准或选择策略。
- laptop 顺序：动作 Decisions → 自适应 → 固定大 → 固定小；desktop 为反序，降低顺序趋势与策略完全重合的影响。
- 独立工作目录、SQLite 与 run.lock；两台均固定候选到逻辑 CPU4，1 CPU / 1 GiB。硬件不同，所有质量、时间与成本比较按主机分层，不将双机的两次观察解释为五次重复或统计显著性。

## 环境与可追溯性

`preflight.json` 保存逐文件源码哈希、任务文件哈希、模型配置、提示/动作 schema 哈希、裁判与候选镜像、主机 CPU、Python、价格快照及顺序。执行前再次核验这些字段，使用独占创建的 `execution-freeze.json` 防止重复启动。

laptop 从 desktop 导入原 judge 镜像后本地镜像 ID 不同，登记为独立 task ID；任务数据、合约和初始代码文件保持一致。镜像层与配置等价性另存证据。各主机的实际镜像 ID 独立记录，不冒用 desktop 的运行环境。

`images.json` 核对结果：judge 的 10 层 RootFS、Config、OS/架构相同；candidate 的 Config 相同，7 层中的最后 3 层摘要不同。两台 candidate 内均为 Python 3.12.16，执行 harness 均为 1414 bytes，SHA256 `1a94f4538d6aa82d55d979b3763a86e0e960370f586b704f34598989f8f3d444`，与执行源码一致。保留这一差异，跨主机不宣称完整镜像相同。

## 停止与汇总

每台最多四轮；不自动重试失败轮、不补抽样。若某轮研究或 final 未完成，保留状态与已有候选并停止该主机后续轮次。每台执行到 40 分钟后不再启动新轮；主代理在用户约一小时的总体范围内收尾。

输出全部八个计划位置、final 原始分数与相对 c0 提升、研究/总耗时、dev 合法候选数、各模型请求与 token，以及 CNY/USD 分列估算和未知项。价格沿用当天原批次冻结快照，属于估算，不是账单。旧短批保持独立，不混入本批重复数。

预先关注两项：自适应策略相对固定大模型的质量与成本关系；动作 Decisions 相对规则自适应的增益。两台结果分开展示，即使方向相反也完整保留。

## 执行修订：laptop 会话中断

23:22 轮询确认 laptop 的前台执行会话已以退出码 143（SIGTERM）结束，主机上已无原 runner 进程。首轮动作 Decisions 已完整交付；第二轮自适应仅记录一次分析、零个模型候选、无 final，另有一次 `model_started` 没有对应完成记录。无法从现有证据确定 SIGTERM 的发送方。

23:25 在启动替代尝试前，以 `continuation-freeze.json` 固定修订：保留中断轮及其原始账本，使用同样的代码、任务、镜像、预算与模型重新执行这一未完成格子，然后执行尚未开始的固定大、小模型两组。未根据候选分数选择重试；中断前没有生成候选。新的 `continue_laptop.py` 由持久进程运行，15:48 UTC 后不再启动新轮，给一小时总体范围留出收尾时间。

计划质量对照仍为八格；实际尝试数增加一轮中断。该轮单列，不混入质量对照，但已知请求、Token 和费用计入执行开销；未完成记录对应的请求结果与费用保持未知。这是一次明确登记的基础设施中断续跑，不启用一般自动重试。

23:35 再登记一次执行修订：替代自适应尝试因两次模型 API 超时以 `failed/model_api_error` 结束，已冻结候选并完成 final，分数 139020。该轮不重跑，保留失败状态。`finish-controls-freeze.json` 只授权执行原计划尚未启动的固定大、小模型两格，不以这一策略的 API 失败取消其他独立对照；每格参数、截止时间保持原值。
