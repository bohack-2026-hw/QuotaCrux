# RouteEvo 两个方向的差异与选择依据

版本：v0.3；更新日期：2026-11-14；状态：选题比较历史参考。

团队已于 2026-11-14 确认选择 Research Agent，当前开发按 [Research Agent PRD](research-agent-track-prd.md)及[补充说明](research-agent-clarifications.md)推进。下文保留选题阶段的能力比较和判断依据，不再作为待执行的选赛道流程。

首版的具体任务、Qwen/GPT 两条路径、Docker 环境与 A/B/C 评测划分统一按[开工决策](implementation-decisions.md)执行。

## 1. 核心差异

| 维度 | 日新方向 | Research Agent 方向 |
| --- | --- | --- |
| 要证明的价值 | 系统从前一轮获得经验，让后一轮任务完成得更好 | 系统在资源预算内自主推进研究，交付经过验证的成果 |
| 主要学习位置 | 跨轮次、跨任务实例的经验复用 | 同一研究任务中的假设修正与实验选择；跨任务经验是进一步增强 |
| 主要评估单位 | 旧经验与新经验处理同一批留出任务的结果 | 一个完整研究过程的最终质量、全部成本与完成时间 |
| 用户输入 | 固定的两轮任务、质量约束、预算与初始经验版本 | 研究问题、数据或程序、工具、目标指标和预算 |
| 关键新增能力 | 两轮会话编排、自动经验发布、学习证据与行为差异展示 | 研究计划、证据引用、假设与实验关联、结果解释和最终交付 |
| 主要界面 | 两轮执行、经验变化、同任务对照、回退 | 研究进度、假设与实验列表、预算、最佳候选和成果 |
| 成果形式 | 新经验版本、两轮日志、对照报告、三行进化说明 | 可运行方案、实验记录、指标、研究结论和复现说明 |
| 演示重点 | 为什么第二轮改变了行动，是否确实更好，如何回退 | 为什么选择这个实验，反馈怎样改变下一步，预算换来了什么结果 |
| 常见不成立情形 | 只增加历史上下文，无法证明后续效果；两批不同任务直接比较 | 只循环调用模型或穷举参数，缺少证据、假设和反馈驱动的修正 |
| 决策模型 | 可用来选择执行路径，须比较其全流程收益 | 可用来选择下一实验或升级时机，须比较其全流程收益 |

## 2. 模块级增量

| 共用模块 | 日新增量 | Research Agent 增量 |
| --- | --- | --- |
| Task | 组成 A 学习任务与 B 留出任务清单，冻结输入和配置 | 增加研究问题、基线、允许修改范围和最终成果要求 |
| Run / Step | 关联轮次，记录前后决策差异及提供给决策器的经验 | 关联研究阶段、证据、假设、实验和继续或停止的依据 |
| Evaluation | 保证旧新经验对同一 B 进行公平比较 | 区分运行中的开发验证与独立最终评价 |
| Experience / MemorySnapshot | 自动发布新快照，展示差异及回退后的生效状态 | 增加研究策略的适用条件、收益、失败方向和来源实验 |
| Comparison | 学习前后质量、Token、费用、耗时及适用反例 | 任务基线、研究后结果、相同 Agent 有无经验的对照 |
| 报告与产物 | 生成三行进化说明、演示证据和版本复现信息 | 导出最佳方案、实验账本、最终结果和复现入口 |

这些是现有对象上的关系与字段增量，不要求为每项能力新增服务。具体需求见[日新 PRD](rixin-track-prd.md)与 [Research Agent PRD](research-agent-track-prd.md)。

## 3. 用同一个载体理解差异

默认继续使用共用核心的小型 Python 数据处理任务，避免选赛道时同时重做执行器与评测器。

**日新演示示意：**A 批任务中，系统实际尝试了不同的修正或优化动作，留下验证结果与成本。系统自动生成经验快照；B 批出现同类但未见过的任务，系统参考相关经验选择行动。对照证明它减少了无效尝试或取得了更好结果，并展示经验不适用时的处理。

**Research Agent 演示示意：**给定一个处理程序、正确性约束和资源预算，系统先测量基线、定位耗时，再提出一个可验证的优化假设，修改候选、运行测试和基准测量，根据反馈继续或放弃，最后交付最佳已验证实现。

上述是要支持的行为，具体假设、失败与收益由运行产生，不预写成固定的成功剧本。若选择表格分类，仅替换 Research Agent 的任务工具和评测，执行、记忆、预算与追溯仍复用共用核心。

## 4. 后续工作顺序

| 阶段 | 日新方向 | Research Agent 方向 |
| --- | --- | --- |
| 首要验证 | 新经验能否改善留出任务上的实际行为与结果 | 反馈能否驱动下一轮研究行动，且产物可独立验证 |
| 第一批增量 | 两轮会话、冻结配置、自动经验发布 | 研究问题、基线、证据与假设、实验记录 |
| 第二批增量 | 同任务对照、经验来源、版本回退联动 | 预算内实验选择、候选比较、最终评价与复现 |
| 最后打磨 | 两轮现场节奏、三行说明、回退展示 | 完整研究轨迹、研究成果、质量与成本曲线 |

M1 的执行与验证是两条路线的前提。日新必须接上 M2 的跨轮次经验与 M3 的对照；Research Agent 可在 M1 上补研究流程，并继续完成经验与评测能力。选赛道不必等待 M3 全部完成。

## 5. 决策时间与选择依据

按现有赛事说明，11 月 14 日 10:00 锁定赛道，11 月 15 日 08:00 提交项目。两份 PRD 不改变该时间约束；锁定前根据已有证据选择，剩余开发围绕选定方向完成。

| 已有证据 | 更值得优先考虑的方向 |
| --- | --- |
| 跨轮次经验收益清楚，短任务能稳定展示，对照和回退证据完整 | 日新 |
| 自主研究流程完整，假设与实验关系清楚，预算内已有可复现成果 | Research Agent |
| 两种证据都有 | 结合现场资源和评委补充口径，由团队选择；不同时报名或同时扩展两套产品 |
| 只有界面和调用链，尚无有效验证结果 | 先补一个最小实测；若已接近锁定，按当前最接近验收的路线决策，不把未验证收益写入承诺 |

模型数量、Agent 数量、是否使用新 API 均不单独作为选赛道依据。

## 6. 本阶段保留与后置

两个方向都采用单执行循环、Qwen 常规执行与 GPT-6.1 Sol（xhigh）升级、程序验证、真实资源账本、可追溯经验、版本复现与回退。

专用决策模型、更复杂的模型路由和跨任务族的经验泛化可在主流程成立后做独立对照。旧新经验使用相同的模型与升级规则，避免把模型配置、提示词变化和经验效果混为一谈。

赛道要求参考[官方赛题](https://tcnf5s7xd39g.feishu.cn/wiki/EpxXwbYkkieZrfk0QbRc7wWQnRc)。Research Agent 的本地模型要求按团队提供的 comment1—comment4 补充口径理解。
