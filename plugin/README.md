# QuotaCrux · 本地优先助手

所有请求正常处理，默认由本机 LM Studio 中的 Gemma 回复。远程模型是按需求助的工具；现有 QuotaCrux 性能优化内核是可选能力，不是输入白名单。

## 使用

在 DSH「插件 → 添加插件」安装本目录，新建会话并选择 **QuotaCrux · 本地优先**。历史报告查看使用另一个 **QuotaCrux · 历史回放** 模式，两个模式的职责不同。修改 JavaScript 或 bundle 配置后重启 DSH，再新建会话验证。

可以直接输入普通问题、写作要求、代码问题或项目工作。普通回答流式显示为文字；文件和终端操作使用 DSH 原生工具及权限流程。只有远程 LLM 求助显示为 `remote_llm` 工具调用，本机 LLM 推理不会伪装成工具调用。

演示示例：

- 「请用两句话解释什么是缓存，不要调用远程模型。」
- 「请向远程专家求助，检查缓存越大性能一定越好这个说法。」
- 「优化日志统计，保持正确性并验证性能。」（按需使用现有研究内核）

## 模型与界面

- 本地：`http://127.0.0.1:1234/v1`，模型 `gemma4u-26b`。运行时注册 `quotacrux-local` 适配器并设为本模式的主模型。已验证 LM Studio 16K 上下文、单并发、关闭额外思考的配置。
- 远程：复用 DSH 已配置的 `usa0`，优先 `deepseek-v4.1-flash`；不复制供应商密钥到项目。
- 每轮远程最多一次，包括失败的请求。工具记录包含触发原因、具体子任务、实际返回内容、用量及耗时；未知费用保持未知。
- 界面只增加一行运行文字。正常文本回复、消息持久化、排队、取消和实际工具操作由 DSH 原生运行时负责。

`p0.js` 中的默认项支持 `projectRoot`、`smallBaseURL`、`smallModel`、`largeProvider`、`largeModel`。在 bundle 中对应插件的配置中覆盖这些字段；不要手工重写整个用户 profile。

## 可选研究优化与共享经验

`research_optimize` 接入现有 Python `Runner`、Docker 沙箱、独立正确性与性能验收以及经验快照。目前有验证器的示例为分组聚合、日志统计、区间合并。其他任务继续正常处理，不要求用户选择基准类型，也不把模型建议冒充已验证的实验结果。

真实研究数据写到当前项目的 `.quotacrux/engine/`，同项目会话可以读取其经验快照；与原有赛事评测数据库隔离。回放引用保存到 `.quotacrux/p0/memory/` 并校验源报告哈希。两类数据均被 Git 忽略，聊天记录不会因此自动在会话间共享。

## 开发检查

```sh
cd plugin
pnpm check
pnpm test
```

插件不额外安装运行依赖；本地模型适配器从已运行的 DSH 安装中解析其官方 LLM 接口。真实研究还需要项目的 `backend/.venv` 和可用的 Docker。

当前验证范围见 [运行记录](LIVE-VALIDATION.md)，早期 P0 安装及回放验证见 [历史验证记录](VALIDATION.md)。
